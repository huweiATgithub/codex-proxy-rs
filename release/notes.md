# v3.22.0

## 用量与性能观测

- 用量记录统一保存请求、调度、传输与恢复观测，保留历史记录的诊断信息
- 延迟明细区分上游性能、请求观测与传输观测，展示上游返回的响应耗时、引擎耗时、TTFT 和 Token 间隔等指标
- 输出速率改用同一完成响应的上游时间戳计算，避免把网关等待与传输时间计入生成耗时；缺少有效上游时间戳时显示「—」
- 首字等待按首个输出项开始事件计时，不再把其他结构事件计为首字

## 修复与改进

- 账号与 Key 表单的分组选择使用轻量查询，避免加载选择项时重复计算分组聚合统计
- Codex 配置导出统一使用 `config.toml` 中的 Provider Bearer 鉴权；CC Switch 导入对齐 4.0.4 支持的连接信息与用量查询字段
- 改进 Codex 0.162 协议兼容：Grok 转换采用最新的增量工具声明，修正同名工具及命名空间成员更新；流内错误的 `Retry-After` 解析与官方头部处理语义保持一致
- 配置发布复用未变化的插件实例，减少进程重建；完善插件状态迁移失败后的恢复与发布流程，保留进行中请求使用的实例
- 修复 PostgreSQL 事务开始被取消后，连接复用可能残留未结束事务的问题

## 升级事项

- 从 v3.21.3 升级会自动执行数据库迁移 `0025_request_observation.sql`，回填现有请求观测并调整存储结构；升级前备份数据库，停止共用该数据库的旧版本实例，为历史请求回填预留时间
- 迁移完成后不能仅切回旧二进制或镜像回滚；如需回退，应同时恢复升级前的数据库备份
- 历史记录缺少新增的上游性能数据时，相应指标保持空缺，输出速率显示「—」
- 手动配置 Codex 时使用完整的 `config.toml` 模板，无需另外生成 `auth.json`；CC Switch 4.0.4 会重建配置，导入连接后如需原生生图等模板设置，请核对并补齐对应配置
