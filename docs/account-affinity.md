# 会话账号绑定

本文定义 `gateway-core::account::affinity` 的职责、接口与状态约束。OpenAI Provider 使用它为同一
客户端会话保留一个上游账号，使根线程、子线程及辅助请求使用一致的账号身份。调用者可见的请求与恢复规则
见 [Responses 接口](api.md#responses-请求与传输)，账号范围、并发与执行边界见
[系统架构](architecture.md#6-路由账号范围与-continuation)

## 职责与接口

账号绑定是独立模块，不读取 Codex 请求、响应正文或网络错误，也不实现账号评分、容量队列和上游传输

| 所属模块 | 职责 |
| --- | --- |
| 协议解析与 OpenAI Provider | 从明确的客户端会话身份派生不透明绑定键，隔离 Client Key 与 Provider；区分会话、线程和缓存路由身份 |
| `account::affinity` | 当前账号绑定、允许切换的原因、发送前原子裁决、绑定代次与有效期语义 |
| 账号选择与 OpenAI credential | 提供账号资格和故障事实，按已有策略选择新账号，取得凭据与容量租约，执行有界等待 |
| `gateway-store` | 实现原子读取、条件写入和条件续期；不解释账号是否应当切换 |
| Provider 执行与 continuation | 在发送前取得有效绑定，检查请求是否可在该账号发送，维护续接与交付边界 |
| 响应反馈 | 更新账号 credential、quota、cooldown 等已确认事实；不持有绑定写入或续期能力 |

模块输入只包含经过解析的绑定键、当前绑定观察、账号资格和封闭的切换原因。账号适配器提供固定账号的
资格检查与容量预留，以及需要新绑定时的候选选择；具体凭据、调度策略和等待队列留在适配器内

存储接口返回明确的“缺失”或当前绑定，并以同一次原子操作比较预期状态、写入绑定或续期。
业务接口返回已确认的账号及绑定 token，或需要重新读取的冲突；调用方不能把任意账号 ID 直接覆盖为当前绑定。
响应完成不属于此接口的输入

## 绑定键与当前状态

绑定键专用于账号绑定，并包含 Client Key、Provider 和客户端会话的隔离范围。同一逻辑会话的根线程、
子线程与嵌套子线程使用同一个键；线程 ID 不能再派生独立账号绑定。没有明确会话身份的请求执行普通选号，
不通过正文内容猜测会话

Codex 的逻辑会话身份与缓存路由身份分别解析。明确的 `client_metadata.session_id` 或
`x-codex-turn-metadata` 中的 `session_id` 优先于会话请求头；缺少逻辑元数据时才使用
`session-id` 及支持的入站别名。`prompt_cache_key` 和用于上游缓存的会话头保持各自协议语义，
不因账号绑定而重写。原始 JSON 辅助端点从其明确的会话字段取得相同的绑定身份。
Codex Live 引导请求明确提供 `session-id` 或 `x-session-id` 时与 Responses 共享账号绑定；
通话建立后的 sideband 与 hangup 始终使用创建通话时的账号

每个键只保存一个当前状态：

```text
Binding = { account_id, token }
```

`token` 是不透明的当前绑定代次，首次绑定或切换账号时重新生成，同账号续期时保持不变。
不保存前任账号、账号选择历史、失败账号列表或响应完成记录。下一次决策仅使用当前绑定、当前账号事实与
本次请求约束；已经离开的账号恢复可用不会主动触发回切

比较必须匹配完整的当前 token，不能只比较账号 ID。账号经历 A → B → A 时，两次 A 属于不同代次；
旧请求也不能把已过期的绑定当作仍然存在。缺失与已绑定是不同的预期状态，比较失败后重新读取，不能
以“键已不存在”为理由直接提交旧观察对应的切换

## 保留与切换账号

当前账号是请求的固定 owner。评分、权重、轮转策略、插件显式选号和同账号重试次数都不能越过它。
只有确认下列事实时，发送前决策才能重新选择账号：

| 允许切换的事实 | 依据与边界 |
| --- | --- |
| 真实额度耗尽 | Provider 已解析的账号额度或明确上游额度拒绝；普通 `429`、容量不足和 `Retry-After` 本身不构成依据 |
| 不可恢复的认证失效 | 凭据恢复已按所属流程判定为不可恢复；令牌临近过期、正在刷新或单次可恢复的 `401` 不构成依据 |
| 明确的账号封禁或验证要求 | 上游证据指向账号本身不可用；网络、代理路径、握手或一般风控挑战不能仅凭状态码归入此类 |
| 本地账号停用或删除 | 当前账号目录确认账号已停用或不存在 |

并发满载、请求间隔、排队、暂时限流、容量冷却、超时、连接失败、模型容量不足和一般服务端错误只允许
同账号等待、同账号安全重试或向客户端返回错误。等待关闭、队列满或等待超时也不允许另选账号

账号范围或模型政策使本次请求不能使用当前 owner 时，拒绝本次请求并保留绑定；请求特有的不兼容不属于
账号失效。发生允许的切换但没有合格替代账号时也保留当前状态，返回相应错误，不清空绑定以绕过限制

## 统一的发送前流程

首次绑定、保留账号和切换账号都经过同一发送前流程；每个重试也重新进入该流程，不能复用旧的账号选择结果

1. 读取当前绑定，取得明确的缺失状态或 `{ account_id, token }`
2. 已绑定时检查 owner 的当前事实；可用则固定该账号，只有封闭的允许原因才能进入候选选择
3. 缺失或允许切换时，按本次冻结的账号范围、模型政策与调度策略选择候选
4. 为选定账号取得凭据与容量租约；暂忙时等待原账号，等待唤醒后重新检查当前绑定与账号事实
5. 发送前原子比较预期状态；首次绑定或切换写入新 token，保留 owner 则按当前 token 续期
6. 比较冲突时释放未使用的容量租约，按存储返回的当前状态重新决策；只有成功取得发送前裁决后才能发送

并发首次请求以原子裁决的 winner 为准；候选评分或先取得容量不代表已经取得账号绑定。
并发切换同样只有一个 winner，其他请求必须按当前状态重算，不能用旧观察覆盖新绑定

发送前裁决是并发请求的绑定生效点。此前已获准发送或已在途的请求可以完成在原账号上的执行，不能从响应
完成顺序反推最新 owner。请求成功、失败、取消和下游断开都不写入或续期绑定；失败只更新所属账号事实，
由下一次发送前决策决定是否允许切换

## 有效期与存储失败

绑定使用 **7 天滑动 TTL**，每次成功的发送前裁决续期。TTL 不依赖响应完成，也不因账号健康反馈、后台
任务或只读查询刷新。绑定只持有账号身份，不持有整个请求生命周期的锁

Redis 确认键过期或丢失后，该键按未绑定会话处理，下一次请求重新选择并生成新 token。
存储超时、连接错误和无效记录均不是“缺失”；无法确认当前 owner 或原子写入结果时停止发送并返回存储错误，
不能降级为普通选号。条件续期失败也必须重新读取，不能无条件补写旧账号

## Continuation 与传输

绑定模块不读取 `previous_response_id`，不保存 transcript，也不决定请求是否可以重放。
已有原生续接仍必须匹配创建它的 Provider 与账号；当前绑定已不允许该账号时，不能为了续接而恢复前任账号

Provider 和 continuation 协调器负责判断是否需要客户端完整重放。仅有增量输入时不能把它发送给新账号；
客户端按恢复合同提交完整历史后，再走同一个发送前流程解析当前 owner。发送结果不明或已经交付输出的请求
仍受既有重放限制。当前绑定命中不能证明客户端携带的不透明 turn state 属于该账号；新账号的新链必须丢弃
不属于它的连接、previous response 与 turn state，不能据此假定加密上下文可跨账号复用

连接缓存、WebSocket 错误计数及 HTTP 回退按线程或传输会话独立维护，不能用共享账号绑定键合并。
根线程和子线程共用账号，不意味着共用上游连接或故障预算

## 验证不变量

- 根线程、子线程、嵌套子线程及同会话辅助请求使用同一绑定，Client Key 与 Provider 之间互不串用
- 缓存路由 ID 与逻辑会话 ID 不同时，仍按逻辑身份绑定账号并保留原缓存字段
- 首绑、切换、重试和并发冲突都经过同一个发送前裁决；未获准的候选不发送请求
- 每种允许切换的事实有对应场景，临时故障、容量争用、权重变化及插件选号均不能越过当前 owner
- 迟到响应不改变当前绑定或 TTL，取消与失败不把绑定恢复为前任账号
- 旧 token 不能覆盖新代次，包括 A → B → A、TTL 过期后重新绑定及续期竞争
- 七天滑动 TTL 在发送前刷新；真实缺失可重新绑定，存储故障禁止 fail open
- 续接需要完整重放时不向其他账号发送增量，不按前任账号路由；线程间传输回退互不污染
